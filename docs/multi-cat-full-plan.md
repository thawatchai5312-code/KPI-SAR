# แผน: ตัวชี้วัดที่อยู่หลายหมวด ขึ้นข้อมูลเต็มทุกหมวด (ยังติดป้ายซ้ำ)

สถานะ: **แผน รอผู้ใช้สั่ง "เริ่มได้"** · แก้เฉพาะ `src/Index.html` (การแสดงผล) · ไม่แตะเซิร์ฟเวอร์/ข้อมูลในชีต · ขึ้นลิงก์ทดสอบก่อน แล้วผู้ใช้สั่งขึ้นหลัก

## ตอนนี้
| หน้า | หมวดแรก | หมวดถัดไป |
|---|---|---|
| หน้าแรก (การ์ด/ตาราง) | การ์ด/แถวเต็ม | **ไม่มีการ์ด/แถว** (มีแค่ชื่อในแถบซ้าย 🔗 กดแล้วพาไปการ์ดหมวดแรก) — `renderList` ใช้ `uniqueById` |
| สรุปรายงาน (จอ + PDF) | ตารางผล + กราฟ/รายละเอียด/ที่มา/ผู้รับผิดชอบ | ตารางผลขึ้น · กราฟ/รายละเอียด = กล่อง "🔗 เป็นตัวชี้วัดเดียวกับ…" (`prRefBlock`) |
| SAR (จอ + Word) | ตารางผล + กราฟ/รายละเอียด/เอกสารแนบ/PDCA | ตารางผลขึ้น · ที่เหลือ = "ดูที่หมวดนั้น" (`sarBlockHtml`, `sarBuildDocx`) |
| CLT | เต็มทุกกลุ่มโรคอยู่แล้ว · ข้อความวิเคราะห์แยกต่อกลุ่มโรค | ไม่มีป้ายบอกว่าอยู่หลายกลุ่ม |

## กติกาใหม่ (ผู้ใช้เลือก)
- ทุกหมวดที่ตัวชี้วัดอยู่ = **ข้อมูลเต็มเหมือนกันหมด** (ผล กราฟ รายละเอียด/วิเคราะห์ ที่มา เอกสารแนบ ผู้รับผิดชอบ PDCA ฯลฯ) — เป็นตัวชี้วัดเดียวกัน (รหัสเดียว) แก้จากหมวดไหนก็แก้ตัวเดียวกัน แล้วทุกหมวดเปลี่ยนตาม
- **ป้ายซ้ำ**: "หมวดแรก" = หมวดแรกตามลำดับที่แสดงในหน้านั้น
  - หมวดแรก: ป้ายเดิม `🔗 อยู่ใน n หมวด: …`
  - หมวดถัดไป: ป้ายสีต่าง `🔁 ซ้ำ — ตัวเดียวกับ ข้อ X <Part › หมวดแรก>` (+ ข้อมูลเต็มเหมือนกัน)
- ไฟล์ Export (PDF สรุปรายงาน, Word SAR) **ขึ้นเต็มทุกหมวดเหมือนบนจอ** + ข้อความป้ายซ้ำ
- CLT: ข้อความวิเคราะห์ **คงแยกต่อกลุ่มโรค** (ไม่ย้าย/ไม่รวมข้อมูล) · เพิ่มป้ายซ้ำ **เฉพาะบนจอ** (PowerPoint คงเดิม)

## แก้ทีละหน้า
### 1. หน้าแรก (การ์ด + ตาราง · ทั้ง 3 มุมมอง)
- `renderList`: ใช้ `getOrderedKpis()` เต็ม (การ์ด/แถว 1 ใบต่อ 1 หมวด) แทน `uniqueById` — โครงเดิมรองรับอยู่แล้ว (`placementsOf`/`key`, `editingKey`, `rerenderCard`/`tblRerenderRow` วาดทุกใบของรหัสนั้น, `findPlacement`)
- ป้าย: การ์ด (แถบป้ายบนการ์ด) + ตาราง (ใต้ชื่อในช่องชื่อ) — หาหมวดแรกจากลำดับรายการที่แสดงอยู่ (`firstKeyOf` คำนวณครั้งเดียวต่อการวาด)
- เลขข้อตาราง (`tblNumbers`) เก็บตาม **key** (หมวดละเลข) แทนตามรหัส · การ์ดใช้เลขตามหมวดอยู่แล้ว
- จำนวน: แถบแบ่งหน้า/แถบตาราง/ผลค้นหา แสดง "n รายการ (m ตัวชี้วัด)" เมื่อมีตัวซ้ำ (แบบหน้าสรุปรายงาน) · ปุ่มมุมมอง/ตัวกรอง/แถบซ้าย นับตัวชี้วัดไม่ซ้ำเหมือนเดิม · แบ่งหน้าการ์ดนับเป็นรายการ
- กดชื่อในแถบซ้าย (`goToKpi(id, key)`): ไปการ์ด/แถว **ของหมวดที่กด** (เดิมไปหมวดแรก) · มาจากหน้าติดตามงาน/ป้ายตัวแม่ (ไม่มี key) = หมวดแรกเหมือนเดิม
- ไฮไลต์ตัวบนจอในแถบซ้าย (`.in-view`) เทียบตาม key (ไม่ไฮไลต์ทุกหมวดพร้อมกัน)
- `liveListSig` (ตรวจว่ารายการเปลี่ยนตอนอัปเดตอัตโนมัติ) ใช้ key ทุกหมวด
- แก้ไข: กด ✏️ ที่หมวดไหน = แก้ตัวนั้นในการ์ด/แถวนั้น (มีได้ทีละใบเหมือนเดิม) · บันทึกแล้ววาดทุกหมวดใหม่ · ระหว่างแก้ การ์ดหมวดอื่นของตัวเดียวกันแสดงค่าก่อนแก้ (เหมือนอัปเดตอัตโนมัติที่ข้ามตัวที่กำลังแก้) · กดแก้หมวดอื่นของตัวเดียวกันระหว่างมีข้อมูลค้าง = ถามบันทึก/ทิ้งก่อน (`guardUnsaved` เดิม)

### 2. สรุปรายงาน (จอ + PDF)
- ตัด `prRefBlock` → ทุกหมวดใช้ `prBlock` เต็ม · หมวดแรกมี `prPlacesNote` (เดิม) · หมวดถัดไปมีป้ายซ้ำ
- KPI รายบุคคล (👤) ใช้เส้นทางเดียวกัน → เต็มทุกหมวดเช่นกัน

### 3. SAR (จอ + Word + หน้าต่างตัวอย่าง Word)
- `sarBlockHtml` / `sarBuildDocx` / ตัวอย่าง (`pvCat.rows`): ทุกหมวดเต็ม (กราฟ รายละเอียด เอกสารแนบ PDCA) + ป้ายซ้ำ · กราฟ PNG ใน Word จำต่อรหัส (สร้างครั้งเดียว ไม่ช้าลงตามจำนวนซ้ำ)
- **PDCA กรอกได้ทุกหมวด เป็นข้อความเดียวกัน** (กุญแจ `PDCA|<รหัส>` เดิม):
  - กล่อง PDCA เปลี่ยน `id="sar-box-<รหัส>"` (ซ้ำกันไม่ได้) → `data-box`; ฟังก์ชัน `sarBox` → หาได้ทุกกล่องของรหัสนั้น
  - พิมพ์ในกล่องหนึ่ง → ข้อความกล่องอื่นของตัวเดียวกันตามทันที (ไม่วาดหน้าใหม่) · ปุ่มบันทึก/ยกเลิก/แถบ "คนอื่นเพิ่งบันทึก" อัปเดตทุกกล่อง
  - ปุ่ม ➕ใส่หัวข้อ / ⬇ดึงจากการวิเคราะห์เดิม / น้องเป้า: ใส่ข้อความทุกกล่อง โฟกัสกล่องที่กด
- ความคืบหน้า/จำนวน "เลือก n ตัวชี้วัด" นับไม่ซ้ำเหมือนเดิม

### 4. CLT (เฉพาะบนจอ)
- แถบซ้าย (แถวตัวชี้วัดในกลุ่มโรค) + หน้าผลลัพธ์: ตัวที่อยู่หลายกลุ่มโรค — กลุ่มแรกป้าย `🔗 อยู่ใน n กลุ่มโรค: …` · กลุ่มถัดไป `🔁 ซ้ำ — ตัวเดียวกับในกลุ่ม <กลุ่มแรก> (ข้อความวิเคราะห์แยกต่อกลุ่มโรค)` · ลำดับกลุ่มตาม `cltGroups()`
- ไม่แตะข้อมูล/PowerPoint

## ไม่แตะ
เซิร์ฟเวอร์ทุกไฟล์ · ข้อมูลในชีต · หน้าติดตามงาน · 🏅 คะแนน KPI · ระบบสอน (ข้อความเดิม "ตัวชี้วัดเดียวกันแสดงได้หลายหมวด แก้ที่ไหนก็เปลี่ยนทุกหมวด" ยังถูก) · คู่มือ (อัปเดตเมื่อผู้ใช้สั่ง)

## ตรวจแผนซ้ำ — จุดเสี่ยงและวิธีกัน
| จุดเสี่ยง | กัน |
|---|---|
| id ซ้ำใน DOM เมื่อตัวเดียวกันขึ้นหลายใบ | หน้าแรก: ช่อง `ed-*`/`dirty-mark` มีเฉพาะใบที่กำลังแก้ (ทีละใบ) · การ์ดใช้ `card-<key>` · ช่องเอกสารแนบใช้ `data-links-for`/`data-links-ro` + `querySelectorAll` อยู่แล้ว · SAR เปลี่ยน `sar-box-<id>` เป็น data attribute (ข้อ 3) · CLT แสดงทีละหัวข้อ ไม่ซ้ำ |
| PDCA สองกล่องพิมพ์ไม่ตรงกัน / บันทึกค่าผิดกล่อง | ข้อความร่างเก็บที่เดียว (`sar.drafts` ต่อรหัส) + สะท้อนทุกกล่องทันที · `sarRender` ยังรอจนเลิกพิมพ์ (`focusout`) |
| แก้หมวด A ค้าง แล้วอัปเดตอัตโนมัติวาดหมวด B ทับ | `livePoll` ข้ามรหัสที่กำลังแก้ทั้งรหัส (เดิม) → หมวด B คงค่าเดิมจนบันทึก แล้ว `rerenderCard` วาดทุกหมวด |
| เลขข้อในตาราง/ไปผิดแถว | `tblNumbers` เปลี่ยนเป็นต่อ key · `goToKpi` ใช้ key ที่กด · `tblEnsureRendered(key)` เดิม |
| จำนวนในปุ่ม/ตัวกรองเพี้ยน | ใช้จำนวนไม่ซ้ำ (`uniqueById`) ตามเดิมทุกจุดที่เป็น "จำนวนตัวชี้วัด" — เปลี่ยนเฉพาะรายการที่วาด |
| ตารางยาวขึ้น ช้าลง | ตารางวาดทีละชุดอยู่แล้ว (`TBL_FIRST`/`TBL_CHUNK`) · การ์ดแบ่งหน้า · รายงาน/SAR แบ่งหน้า |
| ระบบสอน/เทสต์เดิมที่นับการ์ด | ระบบสอนใช้ `uniqueById(...)` หาใบแรก ยังใช้ได้ · เทสต์เดิมที่คาดว่า "ไม่มีการ์ดซ้ำ" ปรับตามกติกาใหม่ |
| Word SAR ช้าลงเพราะกราฟซ้ำ | จำ PNG ต่อรหัสระหว่าง Export |

## เทสต์
- ใหม่ `tests/ui79.js`: ตัวชี้วัด 1 ตัวอยู่ 2 หมวด (ข้อมูลสมมติ)
  - หน้าแรก การ์ด+ตาราง: ขึ้น 2 ใบ ข้อมูลเท่ากัน · ป้ายหมวดแรก/ซ้ำถูก · แก้จากหมวดที่ 2 แล้วบันทึก → ชีตเปลี่ยนแถวเดียว + ทั้ง 2 ใบอัปเดต · กดชื่อหมวดที่ 2 ในแถบซ้ายไปใบที่ 2 · เลขข้อในตารางต่อหมวด
  - สรุปรายงาน: ทั้ง 2 หมวดมีกราฟ/รายละเอียด + ป้ายซ้ำ (ไม่มี "ดูที่หมวดนั้น")
  - SAR: 2 กล่อง PDCA · พิมพ์ในกล่อง 2 → กล่อง 1 ตาม · บันทึกครั้งเดียวได้ `PDCA|<รหัส>` · Word มีกราฟ 2 ที่
  - CLT: ป้ายซ้ำในกลุ่มที่ 2
- รันเทสต์ทั้งชุด (เทสต์เดิมที่เกี่ยวกับ goToKpi/ตาราง/รายงาน/SAR: ui25, ui55-ui58, ui60, ui76 ฯลฯ) ปรับเฉพาะที่ขัดกับกติกาใหม่
