## ส่วน A: ผลแบบข้อความ (ระดับ)

### A.1 ที่เก็บ
- เพิ่มคอลัมน์ **AN "ชนิดผล"** ในชีตปีงบ: ว่าง/`ตัวเลข` = แบบเดิม · `ข้อความ` = ผลเป็นข้อความอิสระ
  - `KPI_COLS` 39 → **40** (`src/Auth.js`) + ค่าคงที่ `RESULT_TYPE_COL = 40`, `RESULT_TYPE_HEADER = "ชนิดผล"` (หัวคอลัมน์เติมตอนเขียนครั้งแรก แบบ `SUMMARY_COL`)
  - ทุกที่ที่ใช้ `KPI_COLS` (ค้น `KPI_COLS` ใน `src/`: Forward, Live, Pct, PersonalImport, PullPrev, Tidy, รหัส) ทำงานต่อได้เพราะใช้ความกว้างจากค่าคงที่ — ตรวจทีละที่ว่าไม่ได้ฝังเลข 39 และแถวที่สร้างใหม่ยาวครบ 40
- `rowToKpi_` เพิ่ม `resultType` (`"number"` | `"text"`) · ถ้า `text`: ผลทั้งปี/รายเดือนอ่านเป็นข้อความ trim (ว่าง → `null`, `"-"` → "ไม่มีเคส" แบบเดิม) แทน `cleanValue_`/`cleanMonth_`
  - **ไม่แก้ `cleanValue_`** (NSO import ใช้อยู่)

### A.2 บันทึก (`saveKpiCore_`)
- `item.resultType` แก้ได้เฉพาะ admin/ผอ./QMR (แบบ `summaryMethod`) · ส่งต่อปีถัดไปได้ (เพิ่มใน `FWD_TEXT_FIELDS` / `FWD_FIELD_LABELS`)
- ถ้า `text`: ค่าผลเป็น `String(v).trim()` ยาวไม่เกิน 60 ตัวอักษร · เขียน G–W ของแถวด้วย `setNumberFormat("@")` ก่อน `setValues` (กันชีตแปลง "A" ไม่ได้ แต่ "1/2", "80%" แปลง)
- เปลี่ยน `ตัวเลข → ข้อความ`: ค่าเดิมกลายเป็นข้อความของตัวเลขนั้น · `ข้อความ → ตัวเลข`: ถ้ามีช่องผลที่ไม่ใช่ตัวเลข → **ไม่บันทึก** แจ้งรายการช่อง (ไม่ลบข้อมูลเงียบ ๆ)
- `propagateAnnual_`: ค่าที่เป็นข้อความ เขียนด้วย `setNumberFormat("@")`
- เปลี่ยนชนิดผลเป็น `ข้อความ` → ตั้ง `summaryMethod = "เดือนล่าสุด"` อัตโนมัติ (วิธีอื่นใช้กับข้อความไม่ได้)

### A.3 หน้าเว็บ (`src/Index.html`)
- ช่องตั้งค่า (การ์ด/แถวตาราง/ฟอร์มเพิ่ม ใกล้ "วิธีสรุปผล"): select "ชนิดผล: ตัวเลข / ข้อความ (ระดับ)" — admin/ผอ./QMR
- ช่องผลทั้งปี (`yearInputHtml`) และรายเดือน: ตัวชี้วัดชนิดข้อความใช้ `type="text"` ไม่ตรวจรูปแบบ (`monthIsBad` ข้ามเมื่อ `resultType === 'text'`) · `collectDraft` ส่งข้อความ
- `calculateMonthlySummary(months, method, kpi?)`: ข้อความ → ค่าล่าสุดที่ไม่ว่าง/ไม่ใช่ "-" · `prNum`: ข้อความ → แสดงตามที่กรอก (escape)
- กราฟ (`generateSvgLineChart` ทุกจุดที่เรียก — การ์ด, สรุปรายงาน, SAR, CLT, Word/PowerPoint): ชนิดข้อความ **ไม่วาดกราฟ** แสดงข้อความ "ผลเป็นระดับ — ไม่มีกราฟ"
- สถานะ 3 สี (`periodHasData`) ใช้ได้เลย (เช็ก `!== null`)
- เพิ่มตัวชี้วัด (`addIndicator` / `buildNewKpiRow_`): รับ `resultType`

### A.4 ส่วนอื่นที่ต้องรองรับข้อความ
- `src/Ai.js`: `aiSummary_`/`aiPass_` — ข้อความ = ไม่คิดผ่าน/ไม่ผ่าน, ส่งค่าข้อความใน context ตามเดิม
- `src/PullPrev.js`: คัดลอกข้อความตามเดิม · `pullPrevMonthlySummary_` ชนิดข้อความ = ค่าล่าสุด
- Export Word/PowerPoint/PDF: ใช้ `prNum` ตัวใหม่
- **ไม่แตะ**: NSO import/sync, PCT import

### A.5 เทสต์
- server: บันทึก/อ่าน ผลข้อความ, เปลี่ยนชนิดสองทาง (ทางกลับมีค่าไม่ใช่ตัวเลข = ปฏิเสธ), ส่งต่อปีถัดไป, propagateAnnual_
- UI: ตั้งชนิดข้อความ → กรอก "ดีมาก" รายเดือน/ทั้งปี → บันทึก → การ์ดแสดง + ไม่มีกราฟ + สรุปรายงานแสดงข้อความ

## ส่วน B: ระบบคะแนน KPI

### B.1 รูปแบบในไฟล์ต้นทาง (วิเคราะห์แล้ว)
- แต่ละ KPI ของหัวหน้ามี **น้ำหนัก** (1, 2, …) และ **เกณฑ์ 7 ช่อง** ของคะแนน 2.0 / 2.5 / 3.0 / 3.5 / 4.0 / 4.5 / 5.0
- คะแนนรอบ = **กรอกเอง** ในไฟล์ (สูตรมีแค่ `น้ำหนัก × คะแนน`) · ประเมิน 2 รอบ: รอบ 1 ต.ค.–มี.ค. · รอบ 2 เม.ย.–ก.ย.
- น้ำหนัก/เกณฑ์ **เป็นของคู่ (ตัวชี้วัด, หัวหน้า)** — ตัวชี้วัดเดียวกันของหัวหน้าต่างคนอาจมีน้ำหนัก/เกณฑ์ต่างกัน
- เกณฑ์เขียนหลายแบบ: ตัวเลขล้วน (เพิ่มขึ้น = ยิ่งสูงยิ่งดี / ลดลง = ยิ่งต่ำยิ่งดี) · มีเครื่องหมาย (`<75`, `≥76`, `>5`, `≤ 2 %`) · ข้อความ (`มากกว่า 1`, `1 ครั้ง/ปี`) · ค่าหลายตัว (`6,6,6`) · ว่างบางช่อง · บางแถวไม่เรียงลำดับ (พิมพ์ผิด) · บางเซลล์ถูกชีตแปลงเป็นวันที่

### B.2 ที่เก็บ: ชีตใหม่ `KPI_Score` (แยกจากชีตปีงบ แบบ `SAR_Doc`/`KPI_Links`)
คอลัมน์ (ข้อความทั้งหมด `@`): ปีงบ · รหัสตัวชี้วัด · ผู้รับผิดชอบ (ชื่อบัญชี) · น้ำหนัก · เกณฑ์ 2.0 · 2.5 · 3.0 · 3.5 · 4.0 · 4.5 · 5.0 · คะแนนรอบ 1 (กรอกเอง) · คะแนนรอบ 2 (กรอกเอง) · หมายเหตุ · แก้ไขล่าสุดเมื่อ · โดย
- 1 แถว = 1 คู่ (ปีงบ, รหัส, ผู้รับผิดชอบ) · เกณฑ์เก็บ **ข้อความตามที่กรอก** (คำนวณตอนอ่าน)
- ไฟล์ใหม่ `src/Score.js`: `scoreSheet_`, `scoreRead_(fy)`, `getScoreBoard(token, fy, person)`, `saveKpiScore(token, fy, p)`, `deleteKpiScore(token, fy, p)`, `scoreCompute_(kpi, row)`
- ทุกการเขียน: script lock + `baseRev` (แฮชของแถว) + `bumpDataVersion_(fy, [], user, "SCORE")` (`pollChanges` ส่ง `docs` มี `"SCORE"` ให้หน้าเว็บดึงใหม่)

### B.3 การคิดคะแนน (`scoreCompute_` ฝั่งเซิร์ฟเวอร์ที่เดียว หน้าเว็บแค่แสดง)
1. **ผลรอบ** = สรุปผลรายเดือนของรอบนั้นตาม `summaryMethod` ของตัวชี้วัด (รอบ 1 = ต.ค.–มี.ค. ช่อง 0–5, รอบ 2 = เม.ย.–ก.ย. ช่อง 6–11) · ไม่มีผลในรอบ = ยังไม่มีคะแนน
2. **แปลงเกณฑ์** ทีละช่อง → `{op, num}` (`op` จาก ≥ > ≤ < = หรือคำ "มากกว่า/น้อยกว่า/ไม่เกิน/ไม่ต่ำกว่า…" แบบ `pimpTarget_`; ตัด %, "ร้อยละ", หน่วยท้าย) · ช่องว่างข้าม · ค่าหลายตัว/วันที่/อ่านไม่ได้ = ช่องนั้นใช้ไม่ได้
3. **ทิศทาง**: เทียบเลขช่องแรกกับช่องสุดท้ายที่ใช้ได้ (มากขึ้น = ยิ่งสูงยิ่งดี, น้อยลง = ยิ่งต่ำยิ่งดี) · เท่ากัน/มีช่องเดียว = ดูเครื่องหมายเป้าหมายของตัวชี้วัด (≤ < = ยิ่งต่ำยิ่งดี)
4. **คะแนน** = ระดับสูงสุดที่ผ่าน: ช่องที่ไม่มีเครื่องหมาย ใช้ `≥` (ยิ่งสูงยิ่งดี) หรือ `≤` (ยิ่งต่ำยิ่งดี) · มีเครื่องหมายใช้ตามนั้น · ไม่ผ่านช่องใดเลย = **0**
5. ตัวชี้วัดชนิดข้อความ (ส่วน A): คะแนน = ระดับที่ข้อความเกณฑ์ตรงกับผล (ไม่สนช่องว่าง/ตัวพิมพ์)
6. **คำนวณไม่ได้** (ไม่มีช่องที่ใช้ได้ ช่องไม่เรียงตามทิศ หรือข้อความไม่ตรง) → แสดง ⚠️ "คำนวณไม่ได้ — กรอกคะแนนเอง"
7. **คะแนนกรอกเอง** (รอบ 1/รอบ 2) ถ้ามี **ใช้แทนคะแนนที่คำนวณ** · ค่าที่รับ: 0–5 ขั้นละ 0.5
8. คะแนนถ่วง = น้ำหนัก × คะแนน · รวม = Σ คะแนนถ่วง · เต็ม = Σ (น้ำหนัก × 5) · ร้อยละ = รวม/เต็ม × 100

  - ตรงกับตัวชี้วัดในระบบ (ชื่อเหมือนกันหลังตัดช่องว่าง/เลขข้อ) **~61** · คล้าย (≥ 80%) **~23** · ใหม่ **~113**

  - เป้าหมาย: เซลล์รูปแบบ % ถูกเก็บเป็น 1 = 100% (ต้องอ่านค่าที่แสดง) · มีเป้าหมายเป็นคำ (เช่น ระดับคุณภาพ) → ชนิดผลข้อความ

  - ผลรายเดือน: มีบางชีต บางเดือน · มีค่าที่ไม่ใช่ตัวเลข (`1(…)`, `6,6,6`, ข้อความสรุป)
  - หลังรายการหลักมีส่วน "KPI กลาง ปีงบ 2570" หรือแถวที่ขึ้นต้น `rd` → **หยุดอ่าน**
  - บางคนมีหัวข้อกลุ่ม (แถวไม่มีลำดับ/เป้า) ตามด้วยแถวย่อย `- OPD`, `- IPD`

### C.4 จับคู่
- **คน → บัญชี**: ชื่อต้นตรงกับบัญชีเดียว = ใช้บัญชีนั้น · ตรงหลายบัญชี = ให้ admin เลือก (ใช้กติกาชื่อซ้ำ/นามสกุลเดิม) · ไม่มีบัญชี = admin เลือก "สร้างบัญชีใหม่ (tier head)" หรือ "ใช้บัญชีที่มี" · คนที่มี 2 ชีต = แสดงทั้งคู่ ให้ admin ติ๊กชีตที่จะใช้ (ค่าเริ่มต้น: ติ๊กชีตที่มีคอลัมน์น้ำหนัก/เกณฑ์)

- **ในไฟล์เอง**: ชื่อเดียวกันหลายชีต = ตัวชี้วัดเดียว ผู้รับผิดชอบหลายคน · เป้าหมายไม่ตรงกัน = ⚠️ ใช้ของชีตแรก แก้ได้ในหน้าตัวอย่าง

### C.5 สิ่งที่เขียน (`headKpiCommit`)
- **ตัวชี้วัดเดิม**: ต่อชื่อผู้รับผิดชอบท้ายช่อง Z (`เดิม / ชื่อบัญชี`) ถ้ายังไม่มีชื่อนั้น · **ไม่เปลี่ยนชื่อ/เป้า/ระดับ/หมวด/รายละเอียด** · ผลรายเดือน: เติมเฉพาะเดือนที่ว่างในระบบและในไฟล์เป็นตัวเลข
- **ตัวชี้วัดใหม่**: ผ่าน `buildNewKpiRow_` — ชื่อ · เป้า (`pimpTarget_`; ไม่มีตัวเลข → เก็บข้อความเดิม + `resultType = ข้อความ`) · ระดับ `รายบุคคล` · หน่วยงานตามที่เลือก (หมวดเติมอัตโนมัติ) · ผู้รับผิดชอบ (ทุกคนที่มี KPI นี้ คั่น ` / `) · Template → ที่มา/สูตร (ข้อความ + URL ลิงก์) · วิธีสรุป `เฉลี่ย` · ความถี่ `รายเดือน` · ผลรายเดือนที่เป็นตัวเลข
- **ชุดคะแนน** (`KPI_Score`): 1 แถวต่อ (2570, รหัส, ผู้รับผิดชอบ) — น้ำหนัก + เกณฑ์ 7 ช่องตามข้อความที่แสดงในไฟล์ · **ไม่นำเข้าคะแนนรอบที่กรอกในไฟล์** (ปีงบ 2570 รอบ 1 ยังไม่จบ) · มีแถวอยู่แล้ว = ไม่ทับ (กันทับที่ admin แก้) แจ้งในผล
- **บัญชีใหม่**: แบบ `PersonalImport` (รหัสตั้งต้น บังคับเปลี่ยน) แต่ tier `head` + หน่วยที่เลือก
- ใต้ script lock · สำรองชีตปีงบ 2570 + Users + KPI_Score เป็นชีตซ่อนก่อนเขียน · จด `Tidy_Log` · `bumpDataVersion_(2570, "*", user)` + `"SCORE"` · **รันซ้ำได้** (ผู้รับผิดชอบมีแล้ว = ข้าม, ตัวชี้วัดที่สร้างแล้วจับคู่เจอเป็นตัวเดิม)
- ข้อความในเซลล์ที่เขียนใหม่ตั้ง `@` ก่อนเขียน (กันชีตแปลง % / วันที่ — ดู `docs/edit-bugs-plan.md` ข้อ 1)
