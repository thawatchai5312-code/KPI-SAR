# สรุปแนวทางการสร้างเว็บแอป (ต้นแบบจากระบบจัดการตัวชี้วัด KPI SAR)

เอกสารนี้สรุปวิธีคิด โครงสร้าง และบทเรียนจากการสร้างระบบนี้ เพื่อใช้ปรับปรุงต่อ หรือเป็นต้นแบบสร้างเว็บแอปใหม่
(ไม่มีข้อมูลจริง/รหัสผ่าน/รายชื่อบุคลากร — repo เป็น public)

---

## 0. โครงสร้างโดยรวม

| ส่วน | ใช้อะไร | เหตุผล |
|---|---|---|
| เซิร์ฟเวอร์ | Google Apps Script (V8) | ฟรี ไม่ต้องดูแลเซิร์ฟเวอร์ ผูกกับ Google Sheet ได้ทันที |
| ฐานข้อมูล | Google Sheet (1 ชีต = 1 ตาราง) | คนทำงานเปิดดู/แก้ฉุกเฉินได้เอง สำรองง่าย |
| หน้าเว็บ | `HtmlService` ไฟล์เดียว `Index.html` (CSS + JS ในไฟล์) | ไม่ต้อง build · โหลดครั้งเดียวแล้วทำงานในเบราว์เซอร์ |
| เรียกเซิร์ฟเวอร์ | `google.script.run.withSuccessHandler(...).ชื่อฟังก์ชัน(...)` | ไม่ต้องทำ API เอง |
| Deploy | `clasp push` + `clasp deploy -i <ID เดิม>` | URL `/exec` ไม่เปลี่ยน ผู้ใช้ไม่ต้องเปลี่ยนลิงก์ |
| สิทธิ์เว็บ | `executeAs: USER_DEPLOYING`, `access: ANYONE_ANONYMOUS` | ใช้ระบบล็อกอินของแอปเอง ผู้ใช้ไม่ต้องมีบัญชี Google |

หลักการแบ่งไฟล์ฝั่งเซิร์ฟเวอร์: แยกตามเรื่อง (ล็อกอิน, ปีงบ, อัปเดตสด, เอกสาร, ลิงก์แนบ …) ทุกไฟล์ `.js` เป็น global เดียวกัน
ฟังก์ชันที่ลงท้ายด้วย `_` = private (หน้าเว็บเรียกไม่ได้) — ใช้แยก "ฟังก์ชันภายใน" ออกจาก "API ที่หน้าเว็บเรียก"

## 1. การออกแบบหน้าเว็บ (UI)

### 1.1 สีทั้งหมดอยู่ที่ `:root` — เปลี่ยนธีมที่เดียว

```css
:root {
  --primary-gradient: linear-gradient(135deg, #22b04b, #00733a); /* แถบเมนู หัวหน้าต่าง ปุ่มหลัก */
  --secondary-gradient: linear-gradient(135deg, #7cc71b, #4e9a0c);
  --accent-gradient: linear-gradient(135deg, #f5b41f, #e0730c);  /* ปุ่มเด่น เช่น "เพิ่มตัวชี้วัดใหม่" */
  --danger-gradient: linear-gradient(135deg, #ef4444, #c0262d);  /* ลบ / ยืนยันอันตราย */
  --primary-color: #00733a;   --primary-vivid: #16a34a;
  --secondary-color: #4e9a0c; --accent-color: #e0730c;
  --text-main: #14231a;  --muted: #64748b;
  --line: #e3ebe6;       --soft: #f3f7f4;   /* เส้นขอบบาง / พื้นหลังอ่อน */
  --radius-large: 14px;  --radius-pill: 50px;
  --box-shadow: 0 6px 20px rgba(0,0,0,0.1);
}
```

**เปลี่ยนเป็นธีมสีอื่น:** แก้ค่าใน `:root` ก่อน แล้วค้นสีที่เขียนตรง ๆ ในไฟล์ (เช่น `#16a34a`, `#dcfce7`, `#f0fdf4`, `#86efac` = โทนเขียว)
แล้วแทนด้วยโทนเดียวกันของสีใหม่ (ชุด Tailwind palette ช่วยได้มาก: 50 / 100 / 300 / 600 / 800 ของสีเดียวกัน)

### 1.2 องค์ประกอบหลัก

- **แถบบน (header/nav):** พื้น `--primary-gradient` ติดบนจอ (`position: sticky`) มุมโค้ง เงาอ่อน · ปุ่มเมนูเป็นทรงเม็ดยา (pill) ปุ่มที่เลือกอยู่พื้นขาว
- **หน้าแรก 2 คอลัมน์:** ซ้าย = ผังรายการ (tree) ติดจอ + ตัวกรอง · ขวา = การ์ด/ตาราง · จอ < 1000px เรียงเป็นคอลัมน์เดียว
- **การ์ด (card):** พื้นขาว มุมโค้ง 16–18px ขอบสีตามสถานะ
  - ซ้าย: กล่องเป้าหมาย → กราฟ → ตารางผลรายปี → ตารางรายเดือน
  - ขวา: "info-card" ซ้อนกัน แต่ละกล่องมีสีพื้นของตัวเอง (รายละเอียด = เหลืองอ่อน, ที่มา/สูตร = เทาเขียวอ่อน, เอกสารแนบ = ฟ้าอ่อน, ผู้รับผิดชอบ = เขียวอ่อน + แถบซ้ายเข้ม)
  - สองฝั่งสูงเท่ากัน: ฝั่งขวา `position:absolute` ตามความสูงฝั่งซ้าย ข้อความยาวถูกตัด (`.clip-box` + ไล่สีจาง) แล้วมีปุ่ม "▼ อ่านเพิ่ม"
- **ป้ายสถานะ 3 ระดับ:** 🔴 ต้องแก้ไข / 🟡 รอติดตาม / 🟢 ครบถ้วน — ใช้สีชุดเดียวกันทั้งการ์ด จุดในผังรายการ ตัวกรอง และหน้าติดตามงาน
- **ป้ายเล็ก (chip/pill):** พื้นอ่อน ตัวหนังสือเข้มโทนเดียวกัน มุม 999px — ใช้กับหมวด ระดับ ปีงบ ตัวกรอง
- **มุมมองตาราง (แบบ Google Sheet):**
  - หัวตาราง 2 ชั้น (กลุ่มคอลัมน์ + ชื่อคอลัมน์) ติดบน · คอลัมน์ "ข้อ/ชื่อ" ติดซ้าย · "จัดการ" ติดขวา
  - ปุ่มชิปเปิด/ปิดกลุ่มคอลัมน์ · ข้อความยาวตัด 3 บรรทัด (`-webkit-line-clamp`) กดเพื่อขยาย
  - แถวเยอะ: วาด 60 แถวแรกทันที ที่เหลือทยอยวาดทีละ 40 (กันจอค้าง)
- **หน้าต่าง (modal):** พื้นหลังมืด + เบลอ (`backdrop-filter: blur`) · หัวหน้าต่างไล่สี · เด้งเข้าเบา ๆ (`scale .8 → 1`) · ปุ่มยกเลิกซ้าย / ยืนยันขวา
- **รายการเลือกแบบลอย (dropdown):** `position: fixed` คำนวณตำแหน่งจากปุ่ม (ลงล่าง/ขึ้นบนตามที่ว่าง) ไม่ทำให้ตารางขยับ · ติ๊กได้หลายรายการ · ช่องค้นหา · กลุ่ม "ของฉัน" ขึ้นก่อน · แถวที่เลือกพื้นเขียว · ป้ายชื่อที่เลือกโชว์ใต้ปุ่ม
- **แจ้งเตือน:** toast ล่างกลางจอ (หายเอง) · "กำลังบันทึก…" เต็มจอ กันกดซ้ำ · ป้ายเหตุผลลอยเมื่อชี้ช่องที่ล็อก ("แก้ไม่ได้: …")

### 1.3 กราฟ (เขียน SVG เอง ไม่ใช้ไลบรารี)

`generateSvgLineChart(values, target, labels)` คืน SVG ทั้งก้อน:
- เส้นผล 5 ปี + จุดวงกลม + ตัวเลขบนจุด · พื้นใต้เส้นไล่สีฟ้าจางลง
- เส้นเป้าหมายแดงประ + ป้ายเม็ดยา "เป้าหมาย > 90 %" มุมขวา
- เส้นกริดจาง · แกน Y ปรับช่วงอัตโนมัติจากค่าสูงสุด/เป้าหมาย
- ข้อดี: เร็ว ไม่ต้องโหลดไลบรารี ใช้ซ้ำได้ทั้งเว็บ / พิมพ์ PDF / แปลงเป็น PNG ใส่ Word/PowerPoint (วาด SVG ลง `<canvas>` แล้ว `toDataURL`)

### 1.4 มือถือ
- ทุกอย่างต้องใช้ได้ที่ความกว้าง ~390px: ปุ่มเมนูขึ้นบรรทัดใหม่ได้ ผังรายการพับได้ การ์ดเรียงคอลัมน์เดียว ตารางเลื่อนซ้าย-ขวาในกรอบ
- dropdown/หน้าต่างต้องไม่ล้นจอ (คำนวณจาก `window.innerWidth/innerHeight`)

## 3. การ Export (PDF / Word / PowerPoint) — ทำในเบราว์เซอร์ทั้งหมด

| รูปแบบ | วิธี | หมายเหตุสำคัญ |
|---|---|---|
| PDF | สร้าง HTML ลง `#print-root` แล้ว `window.print()` | `@media print` ซ่อนทุกอย่างยกเว้น `#print-root` · ตั้ง A4/ขอบ/ตัดหน้า (`page-break-inside: avoid`) · ผู้ใช้เลือก "บันทึกเป็น PDF" |
| Word (.docx) | ไลบรารี `docx@9.5.1` | ตัวอักษรไทยต้องตั้ง `size` **และ** `sizeComplexScript` (ตัวหนาต้องตั้ง `boldComplexScript`) ไม่งั้น Word ใช้ขนาดเดิม |
| PowerPoint (.pptx) | ไลบรารี `pptxgenjs@4.0.1` | กราฟเป็นรูป PNG จาก SVG ตัวเดียวกับเว็บ · ตารางยาวต้องแบ่งสไลด์เอง |

- **โหลดไลบรารีตอนกดปุ่มเท่านั้น** จาก jsDelivr **ระบุเวอร์ชันตายตัว** (ไม่ใช้ `@latest`) — หน้าแรกไม่ช้าลง และไม่พังเมื่อไลบรารีออกเวอร์ชันใหม่
- ตัวอย่างบนจอแบ่งหน้า (10/30/50 รายการ) — วาด 300 รายการทีเดียวใช้ ~6 วินาที จอค้าง
- ก่อน Export เตือนสิ่งที่ยังไม่ครบ (เช่น ข้อความที่ยังเป็น "ร่าง")
- **ต้องทดสอบดาวน์โหลดบน `/exec` จริงทุกครั้ง** เพราะหน้าเว็บ Apps Script อยู่ใน iframe sandbox (ที่เครื่องทดสอบผ่านไม่ได้แปลว่าบนเว็บจริงผ่าน)

## 4. ระบบล็อกอิน (ของแอปเอง ไม่ใช้บัญชี Google)

- ชีต `Users`: `Username | Password (hash) | Tier | Departments | MustChangePassword | LastAccess | LastEdit`
- **รหัสผ่านไม่เก็บเป็นข้อความ:** เก็บ `salt$sha256(salt:password)` (salt สุ่มต่อคน) ตรวจด้วยการ hash ซ้ำแล้วเทียบ
- **รหัสตั้งต้น → บังคับเปลี่ยน:** admin สร้างบัญชี/รีเซ็ตด้วยรหัสตั้งต้น และตั้ง `MustChangePassword = TRUE`
  → ล็อกอินครั้งแรกระบบเด้งหน้าเปลี่ยนรหัสก่อนเข้าใช้งาน · เปลี่ยนแล้วตั้งเป็น `FALSE`
  (อย่าเขียนรหัสตั้งต้นจริงลงเอกสาร/repo สาธารณะ)
- **Session:** token สุ่มยาว เก็บใน `CacheService` 6 ชั่วโมง ผูกกับท้าย hash รหัสผ่าน → **เปลี่ยน/รีเซ็ตรหัสแล้ว session เก่าใช้ไม่ได้ทันที**
- **กันเดารหัส:** ผิด 5 ครั้ง ล็อก 5 นาที (นับใน CacheService)
- **สิทธิ์ (Tier):** `admin` | `executive` | `head` | `staff` + หน่วยงานที่สังกัด
  - **ทุกฟังก์ชันที่หน้าเว็บเรียกรับ `token` และตรวจสิทธิ์ที่เซิร์ฟเวอร์เองทุกครั้ง** (`requireUser_(token)`) — หน้าเว็บซ่อนปุ่มเพื่อความสะดวกเท่านั้น ไม่ใช่การป้องกัน
  - สิทธิ์ต่อรายการคำนวณจากข้อมูลล่าสุดในชีตทุกครั้ง (เปลี่ยนผู้รับผิดชอบแล้วมีผลทันที)
- หลังล็อกอิน: เลือกปีงบก่อนเข้าใช้งาน (กันกรอกผิดปี) · ออกจากระบบต้องล้างสถานะทั้งหมด (ตัวกรอง ข้อมูล แบบร่าง) ไม่ให้ติดไปคนถัดไป

## 5. ระบบแนะนำการใช้งาน (Guided Tour) บนหน้าเว็บจริง

- ล็อกอินครั้งแรก → ป๊อปอัปต้อนรับ "เริ่มดูวิธีใช้ / ข้าม / ไม่ต้องแสดงอีก"
- รายการขั้นตอน = `{ selector ของจุดที่จะชี้, ข้อความ, ก่อนแสดงทำอะไร }`
- องค์ประกอบ 3 ชิ้น:
  - `#tour-blocker` โปร่งใสเต็มจอ กันคลิกพลาดระหว่างสอน
  - `#tour-spot` กรอบสีเหลืองรอบจุดที่สอน + `box-shadow: 0 0 0 9999px rgba(15,23,42,.66)` ทำให้รอบนอกมืดลง (สปอตไลต์)
  - `#tour-tip` กล่องข้อความ + ปุ่ม ก่อนหน้า/ถัดไป/จบ วางข้างจุดที่สอนอัตโนมัติ (ไม่ล้นจอ)
- **สอนบนหน้าจริง:** ขั้นแก้ไขข้อมูลเปิดโหมดแก้ไขของจริง ขั้น "เพิ่มตัวชี้วัด/ตั้งค่า" เปิดหน้าต่างจริง แล้วปิด/ยกเลิกให้เมื่อจบ (ไม่บันทึกอะไร)
- ระหว่างสอน **หยุดอัปเดตอัตโนมัติ** (ไม่ให้หน้าจอเปลี่ยนใต้สปอตไลต์)
- "ไม่ต้องแสดงอีก" จำต่อบัญชีที่เซิร์ฟเวอร์ (Script Properties `TOUR_HIDE_V1:<user>`) — เปลี่ยนเครื่องก็ไม่เด้งซ้ำ
- ปุ่ม 🎓 "แนะนำการใช้งาน" ที่แถบบน เปิดดูซ้ำได้ตลอด

## 6. บทเรียนสำคัญ / กฎที่ต้องทำตาม

### 6.1 Apps Script เฉพาะทาง
1. **Apps Script ตัดคอมเมนต์ `//` ใน `<script>` ก่อนส่งหน้าเว็บ** ด้วยตัวตัดแบบง่าย — ถ้าใน `<script>` มี `//` ที่ไม่ใช่คอมเมนต์ (เช่น `"https://..."` หรือ regex `/a\//`) สคริปต์ทั้งก้อนพัง **หน้าเว็บจริงล็อกอินไม่ได้ทั้งที่เทสต์ผ่าน**
   → ในข้อความเขียน `'https:\/\/...'` · ห้าม regex ที่มี `//` หรือเครื่องหมายคำพูด · มีเทสต์ตรวจอัตโนมัติ
2. ห้ามพิมพ์อักขระพิเศษลงไฟล์ตรง ๆ (BOM, control char, U+2028/2029) ใช้รหัส `\u....`
3. **ทุกเส้นทางที่เขียนชีต** ต้องอยู่ใต้ `LockService.getScriptLock()` (หลายคนบันทึกพร้อมกัน)
4. อ่าน/เขียนชีตเป็นก้อน (`getValues` / `setValues`) ไม่วนทีละเซลล์ — เร็วกว่าหลายสิบเท่า
5. คอลัมน์ข้อความที่อาจขึ้นต้นด้วย `=` `+` หรือเป็นรหัสคล้ายตัวเลข ตั้ง `setNumberFormat("@")` **ก่อน** เขียนค่า
6. Deploy ทับ deployment ID เดิม (`clasp deploy -i <id>`) URL ไม่เปลี่ยน

### 6.2 หลายคนใช้งานพร้อมกัน
7. **ตรวจแก้ชน:** ทุกแถวมี "รุ่น" (`rev`) หน้าเว็บส่ง `baseRev` ตอนบันทึก ถ้าไม่ตรง = มีคนแก้ไปก่อน → ให้เลือก ใช้ของล่าสุด / แก้ต่อจากของฉัน / บันทึกทับ (ห้ามทับเงียบ ๆ)
8. **อัปเดตสด:** ทุกการเขียนจด "เลขรุ่นข้อมูล + รายการที่เปลี่ยน" ใน CacheService · หน้าเว็บถามทุก 10 วินาที ถ้าไม่มีอะไรใหม่ตอบทันทีไม่อ่านชีต · มีของใหม่ส่งเฉพาะแถวที่เปลี่ยน
9. **ห้ามวาดทับช่องที่ผู้ใช้กำลังพิมพ์** — การ์ดที่กำลังแก้ไม่ถูกวาดใหม่ แสดงแถบเตือนแทน · ข้อความยาวรอ `focusout` ก่อน
10. **ห้ามวาดใหม่ทั้งหน้าในแท็บที่ซ่อนอยู่** — ตั้งธง "ต้องวาดใหม่" แล้ววาดตอนกลับมาที่แท็บนั้น (เคยทำหน้าเว็บค้าง)
11. รอเซิร์ฟเวอร์ใช้หน้าจอ "กำลังบันทึก…" แบบนับซ้อนได้ + ปลดเองหลัง 90 วินาที (กันค้างถาวร)
12. คำตอบที่มาช้ากว่าคำขอใหม่ (เปลี่ยนปีงบ/ออกจากระบบระหว่างรอ) ต้องทิ้ง — ใช้เลขลำดับคำขอ (`seq`)

### 6.3 ข้อมูลและความปลอดภัย
13. **ฟีเจอร์ใหม่ใช้ชีตใหม่** ไม่เพิ่มคอลัมน์ในตารางหลักที่ระบบอื่นพึ่งพา (เช่น เอกสาร สรพ. → `SAR_Doc`, ลิงก์แนบ → `KPI_Links`)
14. **ลบแบบ soft delete** (เปลี่ยนสถานะเป็น "ลบ") เผื่อกู้คืน · งานแก้ข้อมูลจำนวนมาก (migration/จัดระเบียบ) ต้องสำรองชีตก่อนและรันซ้ำได้ (มี flag "ทำแล้ว")
15. **Escape ทุกข้อความก่อนใส่ HTML** (`esc()`) · ลิงก์จากผู้ใช้ตรวจโดเมนทั้งเซิร์ฟเวอร์และหน้าเว็บก่อนใส่ `href` · ใช้ `target="_blank" rel="noopener noreferrer"`
16. ส่งค่าไปปุ่มด้วย `data-*` attribute แล้วอ่าน `this.dataset` — ไม่ประกอบสตริงลงใน `onclick` (กันอักขระพิเศษทำโค้ดพัง)
17. repo สาธารณะ: ห้าม commit ข้อมูลจริง รายชื่อ รหัสผ่าน/hash · ข้อมูลทดสอบอยู่นอก git

### 6.4 วิธีทำงาน / ทดสอบ / ขึ้นระบบ
18. **วางแผนก่อน → ถามข้อที่ไม่ชัด → รอ "เริ่มได้"** · **แก้เฉพาะที่สั่ง** ไม่แตะส่วนที่ไม่เกี่ยว (ระบบใช้งานจริง)
19. เทสต์ 2 ชั้น:
    - ฝั่งเซิร์ฟเวอร์: จำลอง `SpreadsheetApp`/`CacheService`/`LockService` ด้วย Node (`vm`) แล้วรันโค้ดจริงกับข้อมูลสำเนา
    - หน้าเว็บ: Playwright เปิด `Index.html` จริง แทน `google.script.run` ด้วยตัวเรียกฟังก์ชันเซิร์ฟเวอร์จำลอง · **ดูภาพหน้าจอทุกครั้ง** ไม่ใช่ดูแค่ว่าผ่าน
    - มีเทสต์ตรวจกฎข้อ 1–2 อัตโนมัติ
20. **ขั้นตอนขึ้นระบบ:** เทสต์ครบชุด → ทำลิงก์ทดสอบชั่วคราว (แถบเขียว "CHECK OK") → ผู้ใช้ลองบนเว็บจริง → ลบลิงก์ทดสอบ → deploy ทับลิงก์หลัก → commit/push
21. จดกฎ/บทเรียนลง `CLAUDE.md` ทุกครั้งที่เจอบัคแปลก ๆ กันกลับมาซ้ำ

## 7. ฟังก์ชันอื่นที่สำคัญ (หยิบไปใช้ได้)

- **ข้อมูลรายปี:** 1 ชีตต่อปีงบ ("ปีงบ 2570") รายการเดียวกันข้ามปีเชื่อมด้วยรหัส · trigger รายวันสร้างปีใหม่อัตโนมัติ (1 ต.ค.) และลอกโครงสร้าง/ข้อความจากปีก่อนเป็น **"ร่าง"** (มีป้าย กด "✔ ตรวจแล้ว" ป้ายหาย · ร่างยังไม่นับว่ากรอกแล้ว)
- **1 รายการอยู่ได้หลายหมวด:** เก็บหมวดหลัก + หมวดเพิ่มเติม แสดงเป็นหลาย "การ์ด" ที่ชี้ข้อมูลตัวเดียวกัน (แก้ที่ไหนก็เปลี่ยนทุกที่)
- **หลายมุมมอง + ตัวกรอง:** มุมมอง รพ. / QA / หน่วยงาน · ขอบเขต ของฉัน / หน่วยของฉัน / ทั้งหมด · สถานะ 3 สี · เลขข้อรันต่อเนื่อง (ตัวย่อย 4.1, 4.2)
- **เตือนก่อนออกจากหน้าที่ยังไม่บันทึก** (เปลี่ยนเมนู/ปีงบ/ปิดแท็บ) + ป้าย "● ยังไม่ได้บันทึก"
- **หน้าติดตามงาน:** สรุปความคืบหน้ารายหน่วย/รายคน ตามความถี่การเก็บข้อมูล (เช็กเฉพาะรอบที่ถึงกำหนด)
- **สรุปรายงาน:** เลือกตัวกรอง/หัวข้อ ดูตัวอย่างแบ่งหน้า แล้ว Export · จำตัวเลือกต่อบัญชี
- **เอกสารรับรองคุณภาพ (SAR / CLT):** หน้ากรอกข้อความต่อรายการ + ตัวอย่างเอกสาร + Export Word/PowerPoint · ตาราง Driver Diagram ที่เลือกตัวชี้วัดผูกในช่องได้ และผูกต่อไปตาราง Process Management อัตโนมัติ
- **เอกสารแนบแบบลิงก์ Drive:** เก็บแค่ลิงก์ (ไม่เก็บไฟล์) 1 ลิงก์ผูกหลายรายการ · เลือกรายการด้วย dropdown + ถามยืนยัน "เลือกครบหรือยัง" ก่อนบันทึก
- **บันทึกเวลาเข้าดู/แก้ไขล่าสุด** ต่อรายการ (ส่งเป็นชุด ไม่ให้การคลิกช้าลง)
- **ปุ่มติดตั้งแอป (📲):** หน้า Apps Script อยู่ใน iframe ติดตั้งเองไม่ได้ → แสดงวิธี "เพิ่มไปยังหน้าจอหลัก" ตามเครื่อง (Android / iPhone / คอมพิวเตอร์ / เปิดจาก LINE ให้เปิดในเบราว์เซอร์ก่อน) + ปุ่มคัดลอกลิงก์ · ตั้ง favicon ด้วย `HtmlOutput.setFaviconUrl`
- **เครื่องมือ admin:** จัดระเบียบข้อมูล (รันซ้ำได้ + บันทึกประวัติการแก้) · นำเข้าจากระบบอื่นแบบ three-way merge (เทียบ ต้นทางเดิม / ต้นทางใหม่ / ของเรา แก้เฉพาะช่องที่ต้นทางเปลี่ยนและเรายังไม่แก้) · ตั้งค่าผู้ใช้/สิทธิ์

## 8. เช็กลิสต์เริ่มเว็บใหม่จากต้นแบบนี้

1. สร้าง Google Sheet + Apps Script · ตั้ง `clasp` (`.clasp.json` ชี้ `rootDir: src`) · `appsscript.json` ตั้ง `executeAs` / `access`
2. คัดลอกโครง: ระบบล็อกอิน (`Users` + hash + session + บังคับเปลี่ยนรหัส) · `requireUser_` · lock + เลขรุ่น + อัปเดตสด · `showBusy` / `toast` / modal / `esc()`
3. ออกแบบตาราง (ชีต) ให้มีคอลัมน์ รหัส · แก้ไขล่าสุดเมื่อ/โดย · ตั้งแต่แรก
4. เปลี่ยนสีที่ `:root` + ไล่แทนโทนสีที่เขียนตรง ๆ · ใส่ Google Fonts
5. ทำหน้าแรก (การ์ด/ตาราง) → ฟอร์มแก้ไข + ตรวจแก้ชน → ตัวกรอง → หน้าสรุป/Export
6. ทำเทสต์จำลองเซิร์ฟเวอร์ + Playwright ตั้งแต่ต้น และเทสต์ตรวจ `//` ใน `<script>`
7. Deploy ครั้งแรกด้วย Apps Script editor (ได้ deployment ID) แล้วใช้ `clasp deploy -i` ทับทุกครั้ง
8. ทำระบบสอนการใช้งานเมื่อหน้าจอหลักนิ่งแล้ว (selector เปลี่ยนบ่อยช่วงแรก)
9. เขียน `CLAUDE.md`: กติกาการทำงาน · โครงไฟล์ · คอลัมน์ข้อมูล · บทเรียน — อัปเดตทุกครั้งที่เจอปัญหาใหม่
