# ฟีเจอร์: จัดทำเอกสารส่ง สรพ. (HA reaccreditation)

> สถานะ: **วางแผนเสร็จ ผู้ใช้ตอบคำถามแล้ว — รอคำสั่ง "เริ่มได้" ก่อนเขียนโค้ด**

## สิ่งที่ผู้ใช้ต้องการ

- ผู้ใช้ฟีเจอร์: **หัวหน้าหน่วยงานขึ้นไป** (Tier `head`, `executive`, `admin`)
- เอกสาร 2 ชุด export เป็นไฟล์เพื่อส่ง สรพ.
  1. **แบบประเมินตนเอง SAR ทั้ง 4 Part** (Part I–IV)
  2. **CLT profile ของ PCT**
- ทำ **3 ปีครั้งตามรอบ reaccredit** ไม่ได้ทำทุกปี → 1 รอบเอกสาร = ปีงบที่เลือก (ใช้ข้อมูลของชีต "ปีงบ <พ.ศ.>" นั้น)
- **ข้อมูลทั้งหมดมาจากหน้าเว็บ** — ไฟล์รอบที่แล้ว (SAR Part IV = Word, CLT = Google Slides ใน Drive ของผู้ใช้
  ไม่ใส่ลิงก์ใน repo) เป็น **ตัวอย่างรูปแบบเท่านั้น ห้ามนำข้อความ/ตัวเลขในไฟล์มาใช้**

## คำตอบของผู้ใช้ (ตัดสินแล้ว)

| เรื่อง | ตัดสิน |
|---|---|
| รูปแบบไฟล์ | **.docx (SAR) + .pptx (CLT)** สร้างและดาวน์โหลดจากหน้าเว็บ ไม่ต้องขอสิทธิ์ Google เพิ่ม |
| ข้อความบรรยาย | **หัวหน้ากรอกในระบบ** (ไม่นำเข้าจากไฟล์เดิม ไม่ใช้ AI) |
| ขอบเขต | **ครบ 4 Part + CLT** |
| หัวข้อ SAR Part I–IV | **ใช้หมวด Part I–IV ของมุมมอง "รพ." ในเว็บ** ตามลำดับที่แสดงในเว็บ (ไม่ใช้เลขข้อ 83–97 ของแบบฟอร์ม) |
| การวิเคราะห์รายตัวชี้วัด (ปัญหาที่พบ / การพัฒนาที่ผ่านมา / แผน) | **ช่อง "รายละเอียด/การวิเคราะห์" เดิม** (คอลัมน์ X `templateDetails`) ของปีงบนั้น |
| สิทธิ์ | **หัวหน้าแก้ของหน่วยตัวเอง** · CLT = หัวหน้า PCT · ผอ./QMR/admin แก้ทุกส่วนและ export รวมเล่ม |
| Process flowchart ใน CLT | **เว้นหน้าไว้** ให้แปะรูปเองหลัง export (อนาคตอาจทำฟีเจอร์วาด flowchart ในเว็บ) |
| รอบถัดไป | **เริ่มว่าง + ปุ่ม "คัดลอกจากรอบก่อน" เป็นร่าง** (ทีละหัวข้อ หรือทั้งเล่ม) |

## รูปแบบจากไฟล์ตัวอย่าง (โครงสร้างเท่านั้น)

**SAR Part IV** — A4 แนวนอน ฟอนต์ไทยขนาด ~14pt · แต่ละหัวข้อมี 2 ตาราง
1. ตารางผล: ตัวชี้วัด | เป้าหมาย | ผล 5 ปี (ตัวย่อยเยื้องใต้ตัวแม่ เช่น 1.1, 1.2) · เลข "ตัวชี้วัดที่ N" รันต่อเนื่องทั้งเล่ม
2. ตารางวิเคราะห์: กราฟเส้น 5 ปี + เส้นเป้าหมาย | การวิเคราะห์ PDCA (ปัญหาที่พบรายปี → การพัฒนาที่ผ่านมา → แผนการพัฒนา)
   ตัวที่วิเคราะห์ร่วมกันเขียน "รวมกับตัวชี้วัดที่ N"

**CLT profile** — สไลด์ 2 ส่วน
- ภาพรวม PCT: พันธกิจ/ความมุ่งหมาย · ขอบเขตบริการ · ผู้รับบริการและความต้องการ (ตาราง) · จุดเน้นการพัฒนา ·
  กลุ่มผู้ป่วยสำคัญ (ตารางคะแนน 1–5: High risk / High cost-Long LOS / High volume / New evidence-technology / Complex care) ·
  ตัวชี้วัดตาม 8 มิติคุณภาพ (Access, Continuity, Appropriate, Effective, Efficient, Safe, People-centered, Health promotion) ·
  ความเสี่ยงและมาตรการป้องกัน (ความเสี่ยง | ระดับ | มาตรการ | ผลการติดตาม) · คุณภาพขั้นตอนในกระบวนการดูแล (กระบวนการ | โรค | มาตรการ) ·
  การพัฒนาคุณภาพ/วิจัย/นวัตกรรม (เรื่อง | เป้าหมาย | การพัฒนา | ผลลัพธ์) · แผนพัฒนา (แผน | กระบวนการ | กลุ่มเป้าหมาย)
- รายโรค (Clinical tracer): บริบท · ประเด็นท้าทาย + ความเสี่ยงสำคัญ · Driver diagram (Purpose → Primary → Secondary drivers →
  Change ideas + ตัวชี้วัด) · Process flowchart (รูป) · Process management (กระบวนการ | ข้อกำหนด | ตัวชี้วัด+เป้าหมาย | การออกแบบ) ·
  ผลลัพธ์ 1 สไลด์ต่อตัวชี้วัด (กราฟ 5 ปี + เป้าหมาย + การพัฒนา/ปัญหา/แผน) · แผนพัฒนาต่อไป
- กราฟในไฟล์เดิมเป็นรูปแปะ — ของใหม่สร้างจากข้อมูลในระบบ

## ออกแบบ

### เนื้อหาเอกสาร

**SAR (.docx)** — หัวข้อ = หมวด Part I–IV ของมุมมอง "รพ." ต่อหมวด:
- ข้อความบรรยายของหมวด (กรอกในระบบ — ช่องเดียว มีคำแนะนำหัวข้อ: บริบท / กระบวนการ / ผลลัพธ์ / แผนการพัฒนา)
- ตารางผล 5 ปีของตัวชี้วัดในหมวด (ปีงบ-4 … ปีงบ จากคอลัมน์ G–K) + ตารางกราฟ | การวิเคราะห์ (คอลัมน์ X)
- ตัวชี้วัดที่อยู่หลายหมวด: อยู่ในตารางผลทุกหมวด กราฟ+การวิเคราะห์เต็มครั้งแรก ที่เหลือเขียน "ดูตัวชี้วัดที่ N"
- หมายเหตุที่ระบบใส่ตอนนำเข้า NSO (`TIDY_NOTE_LINE`) ไม่ลงเอกสาร
- ตอน export ติ๊กเอาหมวด/ตัวชี้วัดออกได้ (แบบหน้าสรุปรายงาน)

**CLT (.pptx 16:9)** — ภาพรวม PCT ตามหัวข้อข้างบน + รายโรค
- รายโรค = กลุ่มของหน่วย PCT ในมุมมองหน่วยงาน (`VIEW_PCT_GROUPS`) — หัวหน้า PCT เลือกกลุ่มที่จะใส่ (ค่าเริ่มต้น = ทุกกลุ่มที่มีตัวชี้วัด)
- ตาราง "ตัวชี้วัดตาม 8 มิติ" สร้างจากตัวชี้วัดในกลุ่ม — ระบบเดามิติจากชื่อ (แบบ `VIEW_STAGE_RULES`) แล้วหัวหน้า PCT ปรับได้
- สไลด์ผลลัพธ์: กราฟเส้นแบบ native ของ PowerPoint (แก้ได้) + ข้อความจากคอลัมน์ X
- Process flowchart = สไลด์เปล่ามีหัวเรื่อง

### เก็บข้อมูล: ชีตใหม่ `SAR_Doc` (ไม่แตะ 39 คอลัมน์ของชีตปีงบ)

ปีงบ | เอกสาร (SAR/CLT) | กุญแจหัวข้อ | ชนิด (ข้อความ/ตาราง JSON) | เนื้อหา | หน่วยรับผิดชอบ | rev | แก้ไขล่าสุดเมื่อ/โดย
- ตาราง (ผู้รับบริการ, ความเสี่ยง, driver diagram, process management ฯลฯ) เก็บเป็น JSON 1 เซลล์ต่อหัวข้อ — ตรวจขนาด ≤ 45,000 ตัวอักษร
- ค่าตั้งของรอบ (กลุ่มโรคที่เลือก, มิติที่ปรับ, หมวด/ตัวที่เอาออก) เก็บเป็นแถวในชีตเดียวกัน
- เขียนทุกครั้งอยู่ใต้ `LockService` script lock + ตรวจ `baseRev` กันเขียนทับกัน (แบบ `saveKpi`) + แจ้งเครื่องอื่นผ่านกลไก Live
  (เพิ่มชนิดการเปลี่ยนแปลง "sar" ให้ `pollChanges` — ไม่บังคับโหลดตัวชี้วัดทั้งหมดใหม่)
- คัดลอกจากรอบก่อน: คัดเฉพาะข้อความใน `SAR_Doc` จากปีงบล่าสุดที่มีข้อมูล (คอลัมน์ X เป็นของแต่ละปีงบตามเดิม)

### สิทธิ์ (ตรวจที่เซิร์ฟเวอร์ทุกครั้ง `requireUser_`)

- staff ไม่เห็นเมนู · หน้าที่เรียกได้รับ `token`
- ข้อความหมวด SAR: หัวหน้าที่หน่วยตัวเองเป็นหน่วยรับผิดชอบของหมวด — ค่าเริ่มต้น = หน่วยงาน (คอลัมน์ AA) ของตัวชี้วัดในหมวด, admin/QMR ปรับได้
- การวิเคราะห์รายตัวชี้วัด: แก้ผ่าน `saveKpi` เดิม (สิทธิ์ `getKpiPermission_` เดิม)
- CLT: หัวหน้าหน่วย PCT · ผอ./QMR/admin แก้ได้ทุกส่วน · **export รวมเล่ม = ผอ./QMR/admin** (หัวหน้าดูตัวอย่างบนจอได้)

### หน้าเว็บ: เมนูใหม่ "📑 เอกสาร สรพ."

- เลือกปีงบ (รอบ) · ซ้าย = ผังหัวข้อ (SAR Part I–IV › หมวด, CLT ภาพรวม › หัวข้อ, CLT รายโรค › หัวข้อ) · ขวา = ตัวแก้ไข + ตัวอย่างตาราง/กราฟ
- แถบความคืบหน้า: หัวข้อที่ยังไม่กรอก, ตัวชี้วัดที่ยังไม่มีการวิเคราะห์หรือผลปีล่าสุด แยกตามหน่วย/ผู้รับผิดชอบ + ตัวกรอง "ของฉัน"
- ทำตามกติกาเดิม: `showBusy`/`unbusy`, ห้ามวาดใหม่ในแท็บที่ซ่อน (ตั้ง stale แล้ววาดตอนกลับ), แบ่งหน้า/วาดทีละชุดเมื่อรายการยาว

### Export (ทำในเบราว์เซอร์)

- โหลดไลบรารีจาก CDN เฉพาะตอนกด export: `docx` (Word) และ `PptxGenJS` (PowerPoint) — ระบุเวอร์ชันตายตัว
- กราฟใน .docx: SVG (`generateSvgLineChart`) → canvas → PNG · ใน .pptx: กราฟ native
- ฟอนต์ TH SarabunPSK · A4 แนวนอน · ตัวเลขในเอกสารเป็นเลขอารบิกตามไฟล์ตัวอย่าง (ต่างจากหน้าสรุปรายงานที่ใช้เลขไทย — เปลี่ยนได้ถ้าผู้ใช้ต้องการ)

## ขั้นตอนทำงาน

0. **Spike**: ยืนยันว่าหน้าเว็บ Apps Script (iframe) โหลดไลบรารีจาก CDN และดาวน์โหลดไฟล์ blob ได้จริงบน `/exec`
   — ถ้าดาวน์โหลดไม่ได้ ต้องกลับมาถามผู้ใช้เรื่องทางเลือก
1. เซิร์ฟเวอร์ `src/SarDoc.js`: ชีต `SAR_Doc`, อ่าน/บันทึกหัวข้อ (lock + baseRev + Live), สิทธิ์, คัดลอกจากรอบก่อน, ค่าตั้งของรอบ
2. หน้าเว็บ: เมนู + ผังหัวข้อ + ตัวแก้ไขข้อความ/ตาราง + แก้การวิเคราะห์รายตัวชี้วัด + ความคืบหน้า
3. Export SAR .docx
4. Export CLT .pptx
5. เทสต์ฝั่งเซิร์ฟเวอร์ (สิทธิ์, ชนกัน, คัดลอกรอบก่อน) + UI (Playwright: แก้ไข, export แล้วเปิดไฟล์ตรวจเนื้อหา) + ดูภาพใน `tests/out/`
   — ต้องสร้าง `tests/fixtures/` ก่อน (session ใหม่ไม่มี) จากสเปรดชีตจริง ไว้นอก git
6. อัปเดตคู่มือฉบับเต็ม/ย่อ (Artifact ลิงก์เดิม) → `npm run deploy` → commit → push
