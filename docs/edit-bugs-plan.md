## บัคที่พบ

### 1. ข้อความที่บันทึกถูกชีตแปลงชนิดเอง (สำคัญสุด — ต้องยืนยันกับชีตจริงก่อนแก้)
- **ที่เกิด**: `saveKpiCore_` เขียนช่อง ชื่อ (E) · เป้าหมาย (F) · รายละเอียด (X) · ที่มา/สูตร (Y) · ผู้รับผิดชอบ (Z) · หน่วยงาน (AA) ด้วย `setValue(ข้อความ)` โดย**ไม่ตั้งรูปแบบเป็นข้อความ (`@`) ก่อน**
  (ช่องอื่นที่ระบบเขียน เช่น AI/AK/AL ตั้ง `@` แล้ว) · เส้นทางเพิ่มตัวชี้วัด (`buildNewKpiRow_` → `addIndicator`, `fwdAddToYear_`, `PersonalImport`) เขียนแถวใหม่แบบเดียวกัน
- **อาการที่เป็นไปได้**: Apps Script แปลงข้อความเหมือนพิมพ์ในชีตเอง
  - เป้าหมาย `= 0` (ใช้บ่อยกับอุบัติการณ์) → กลายเป็น **สูตร** ได้ค่า 0 → หน้าเว็บเห็น `0` (เครื่องหมาย = หาย) หรือ `#ERROR!`
  - เป้าหมาย `80%` → ตัวเลข `0.8` · `1/2` → วันที่
  - รายละเอียด/ที่มา ที่ขึ้นต้นด้วย `=` → สูตร → ข้อความหาย/เป็น `#ERROR!`
- **หลักฐาน**: ในข้อมูลทดสอบ (ชุดที่ดึงจากชีตจริง) มีเป้าหมาย `0.8`, `0.5`, `0.9`, `1` ×5, `0` ×8 — เข้ากับรูปแบบ "พิมพ์ 80% → ได้ 0.8" แต่ยังไม่ยืนยัน (อาจตั้งใจพิมพ์แบบนั้นจริง)
- **แผนยืนยัน (อ่านอย่างเดียว ไม่เขียนชีต)**: ฟังก์ชัน admin ชั่วคราว (หรือรันใน editor) อ่าน `getValues` + `getFormulas` + `getNumberFormats` ของคอลัมน์ E, F, X, Y, Z, AA ทุกชีตปีงบ → รายงานเซลล์ที่เป็นตัวเลข/วันที่/สูตร/รูปแบบ % ในคอลัมน์ข้อความ (รหัสตัวชี้วัด + ค่าที่เห็น)
- **แผนแก้**:
  1. ก่อนเขียนช่องข้อความทั้ง 6 คอลัมน์ ตั้ง `setNumberFormat("@")` ที่เซลล์นั้น (ทำแบบเดียวกับ AI/AK/AL ที่มีอยู่) — ใน `saveKpiCore_` และตอนเพิ่มแถวใหม่ (ตั้ง `@` ทั้งช่วง E–F, X–AA ของแถวก่อน `setValues`/`appendRow`)
  2. ข้อมูลเดิมที่ถูกแปลงไปแล้ว **แก้อัตโนมัติไม่ได้** (ไม่รู้ว่าเดิมพิมพ์ `80%` หรือ `0.8`) → ใช้รายงานจากขั้นยืนยันให้ admin/ผู้รับผิดชอบแก้เอง (ถามผู้ใช้ก่อน — ดูข้อ 1 ในคำถาม)
- **เทสต์**: harness จำลองชีตไม่แปลงชนิด → เพิ่มการตรวจใน `tests/t*.js` ว่าทุกช่องข้อความถูกตั้ง `@` ก่อนเขียน (ดักการเรียก `setNumberFormat`) + ทดสอบจริงบน **ลิงก์ทดสอบ** ด้วยตัวชี้วัดทดลอง (เป้าหมาย `= 0`, `80%`)

### 2. ผลทั้งปีพิมพ์ผิดรูปแบบ → ค่าเดิมหายเงียบ ๆ
- **ที่เกิด**: ช่องผลทั้งปีเป็น `<input type="number">` (`yearInputHtml`) อ่านด้วย `getNum` — ถ้าพิมพ์รูปแบบที่ไม่ใช่ตัวเลข (เช่น `1.2.3`, `5-`, `e`; บน Firefox/บางมือถือพิมพ์ `80%` หรือ `1,234` ได้) เบราว์เซอร์ให้ค่า `''` → ส่ง `null` → **เซิร์ฟเวอร์ลบผลปีนั้น** (และส่งต่อไปชีตปีอื่นผ่าน `propagateAnnual_`)
  - ไม่มีข้อความเตือน (ต่างจากผลรายเดือนที่ตรวจ `monthIsBad` แล้วเตือน)
  - `isDirty` ไม่เห็นการเปลี่ยน → ออกจากการแก้ไขโดยไม่ถาม
- **แผนแก้** (`src/Index.html` เท่านั้น): ใน `saveKpiEdit` ตรวจ `el.validity.badInput` ของ `ed-y0…4` → เตือน "ผลปีงบ … กรอกได้เฉพาะตัวเลข หรือเว้นว่าง" แล้วไม่บันทึก (แบบเดียวกับรายเดือน) · `isDirty` นับช่องที่ `badInput` ว่าแก้แล้ว
- **เทสต์**: Playwright พิมพ์ค่าผิดในช่องผลทั้งปี (`page.fill` ค่าที่ `type=number` ไม่รับ หรือจำลอง `badInput`) → ต้องขึ้นเตือน + ค่าในชีตไม่เปลี่ยน

### 3. บันทึกโดยไม่ได้เปลี่ยนอะไร แต่เครื่องอื่นขึ้น "ถูกแก้ไขโดย…" (แก้ชนหลอก)
- **ที่เกิด**: `saveKpiCore_` เขียนผล 17 ช่อง + รายละเอียด + ที่มา **ทุกครั้ง** แม้ค่าไม่เปลี่ยน · ถ้าค่าเดิมในชีตเป็นตัวเลขที่เก็บเป็นข้อความ / เลขไทย / ช่องว่างแบบอื่น การเขียนซ้ำเปลี่ยนชนิดเซลล์ → `rowRev_` เปลี่ยน แต่ `changed = false` จึง**ไม่เรียก `bumpDataVersion_`**
  → เครื่องอื่นยังถือ rev เก่า → กดบันทึกตัวชี้วัดนั้นแล้วขึ้นหน้าต่างแก้ชนกันทั้งที่ไม่มีใครแก้ข้อมูลจริง
- **แผนแก้** (`src/รหัส.js`): หลังเขียนเสร็จ เทียบ `old.rev` กับ `fresh.rev` — ถ้าต่างกันแม้ `changed = false` ให้ `bumpDataVersion_(fy, [old.id], user)` (ไม่ลงเวลาแก้ไข ไม่ส่งต่อปีถัดไป ข้อความยังเป็น "ไม่มีการเปลี่ยนแปลง") · หรือเขียนเฉพาะช่องที่เปลี่ยน (แก้มากกว่า เสี่ยงกว่า — ไม่แนะนำ)
- **เทสต์**: server test — แถวที่ผลเก็บเป็นข้อความ `"80"` → บันทึกค่าเดิม → ต้องมีการ bump และ rev ที่คืนให้หน้าเว็บตรงกับชีต

## ส่วนที่ตรวจแล้วไม่พบบัค
- **ผลรายเดือน**: ตรวจรูปแบบก่อนส่ง (`monthIsBad`) · `-`/NA → "ไม่มีเคส" · ว่าง = ยังไม่กรอก · เซิร์ฟเวอร์แปลงซ้ำด้วย `monthOrNull_`
- **ปีที่ล็อก** (ผลย้อนหลังที่มีชีตต้นทาง): หน้าเว็บปิดช่อง + เซิร์ฟเวอร์ข้ามให้ถ้าไม่ใช่ admin/ผอ./QMR
- **สิทธิ์**: ตรวจที่เซิร์ฟเวอร์ทุกช่อง (ผล/รายละเอียด/ชื่อ/หมวด/ตัวแม่/ระดับ) · ช่องที่ไม่มีสิทธิ์หน้าเว็บไม่ส่ง
- **แก้ชนกัน**: ตรวจ `baseRev` · "บันทึกทับ" ส่งเฉพาะช่องที่ผู้ใช้แก้ (ไม่ลบงานคนอื่น) · "โหลดล่าสุด" ตั้ง rev ใหม่ให้
- **ระหว่างรอบันทึก**: ออกจากระบบ/เปลี่ยนผู้ใช้ หรือเปลี่ยนปีงบ → ไม่เอาข้อมูลไปใส่ผิดที่ · กดบันทึกซ้ำถูกกันด้วย `savingKpi`
- **สถานะ 3 สี**: เดือนที่ถึงกำหนด (ย้อนหลัง 1 เดือน, ต.ค. ยังไม่เช็ก) · ความถี่ไตรมาส/ครึ่งปี/รายปี · ช่วงผ่อนผันการวิเคราะห์ ต.ค.–ธ.ค. · "-" นับว่ากรอกแล้ว
- **ส่งต่อปีถัดไป / ย้าย CLT / ผลทั้งปีไปชีตปีอื่น**: ทำใต้ lock เดียวกัน + bump ครบ

## ข้อสังเกต (ไม่ใช่บัค — ถามผู้ใช้ว่าจะปรับไหม)
- เปิดตัวกรองสถานะ เช่น "ต้องแก้ไข" แล้วบันทึกจนตัวชี้วัดเป็นสีเขียว → การ์ด/แถวยังอยู่ในรายการ (วาดเฉพาะใบนั้นใหม่ กันรายการกระโดด) จนกว่าจะเปลี่ยนตัวกรอง/หน้า

## ลำดับทำงาน (เมื่อสั่ง "เริ่มได้")
1. ข้อ 1 ขั้นยืนยัน (อ่านอย่างเดียว) → รายงานผลให้ผู้ใช้ก่อน
2. แก้ข้อ 1 (ตั้ง `@`), ข้อ 2, ข้อ 3 + เทสต์เฉพาะส่วน
3. ขึ้นลิงก์ทดสอบ → ผู้ใช้ลอง → ขึ้นหลักเมื่อสั่ง
